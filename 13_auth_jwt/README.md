# 📌 Module 13 — Authentication Basics: OAuth2 & JWT

This module covers building a secure token-based authentication system using **OAuth2** password flow and **JWT (JSON Web Token)**.

---

## 🧠 What is JWT (JSON Web Token)?

A **JWT** is a compact, URL-safe way of representing claims to be transferred between two parties. It is cryptographically signed, meaning the client cannot modify it without breaking the signature.

A JWT consists of three parts separated by dots (`.`):
1. **Header:** Contains the token type (JWT) and signing algorithm (e.g., HS256).
2. **Payload:** Contains the claims (user data, expiration time).
3. **Signature:** Generated by signing the Header and Payload with a secret key.

```
xxxxx.yyyyy.zzzzz
Header.Payload.Signature
```

---

## 🔒 Token-Based Auth Flow

1. Client sends username and password via `POST /token`.
2. Server verifies the password (by comparing hashed values).
3. Server generates a signed JWT access token and returns it.
4. Client stores the token and sends it in the `Authorization` header (`Bearer <token>`) for secure routes.
5. Server verifies the token signature and extracts user details.

---

## 🔑 Password Hashing

Never store passwords in plain text! If the database is compromised, all user accounts are exposed.
We use **Bcrypt** (via the `passlib` library) to securely hash and verify passwords.

* **Hashing:** `password` ──> `$2b$12$eD...` (one-way operation)
* **Verifying:** Compare the incoming plain password with the stored hash using Bcrypt.

---

## ⚙️ FastAPI Security Tools

FastAPI provides native classes to handle OAuth2 password flow:
* **`OAuth2PasswordBearer`:** Dependency that looks for the `Authorization: Bearer <token>` header in incoming requests.
* **`OAuth2PasswordRequestForm`:** Dependency that parses form-data containing `username` and `password` during login.

## 🎯 Interview Questions

**Q1. What is JWT and what are its three components?**
> A JSON Web Token (JWT) is an open standard for securely transmitting information between parties as a JSON object. It consists of: 1. Header (algorithm & token type), 2. Payload (user data & expiration), and 3. Signature (cryptographic hash ensuring integrity).

**Q2. Why is token-based authentication preferred over session-based authentication in APIs?**
> Token-based authentication is stateless. The server does not need to store session information in memory or database. Every request contains the token, making it highly scalable and easy to share across multiple servers or microservices.

**Q3. Why should you never store plain text passwords in a database?**
> If the database gets leaked, plain text passwords expose all user accounts immediately. Hashing algorithms like Bcrypt turn passwords into irreversible hashes, securing user credentials even if the raw database is leaked.

**Q4. What is the role of `OAuth2PasswordBearer` in FastAPI?**
> It is a helper dependency that extracts the bearer token from the `Authorization` header (`Bearer <token>`). If the header is missing, it automatically raises a `401 Unauthorized` exception.

**Q5. What is the difference between encryption and hashing?**
> Encryption is a two-way operation (data can be encrypted and decrypted back to plain text using a key). Hashing is a one-way cryptographic operation (data cannot be reversed back to plain text; you can only verify it by hashing a new input and comparing the result).

**Q6. What does `SECRET_KEY` do in JWT generation?**
> The `SECRET_KEY` is a private string kept on the server. It is used to generate the cryptographic signature of the token. Without the correct key, it is mathematically impossible to forge a valid token signature.

**Q7. What is `OAuth2PasswordRequestForm` in FastAPI?**
> It is a dependency that automatically parses OAuth2-compliant authentication details (specifically `username` and `password`) from the HTTP request body sent as `application/x-www-form-urlencoded` form data.

**Q8. How does token expiration protect your application?**
> Access tokens are given an expiration window (e.g., 30 minutes). If a token is intercepted or stolen by an attacker, it becomes useless after the expiration window passes, minimizing potential security damage.
